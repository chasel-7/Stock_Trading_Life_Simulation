系统架构与数据流向设计

基于“混合模式（Hybrid）+ 交易日志校验防作弊”方案

1. 数据流动模型

// 🎮 客户端 (React + LocalStorage)
1. 盘中交易 & 场景决策在本地运行，实现 0 延迟 体验。
2. 每次交易（买入/卖出）在本地追加一条日志：
   { day: 3, stock: "科技-07", action: "BUY", price: 23.5, quantity: 500 }

📊 结算与防作弊 (游戏结束时)
3. 客户端发送数据包：{ 角色信息, 最终资产, 交易日志列表 } 到后端。
4. 后端 (FastAPI) 校验：
   - 重新模拟交易过程，验证买卖价格是否与数据库中真实股票历史行情一致。
   - 重新计算日薪、场景扣费和结算资金，校验最终资产数值是否相符。
   - 通过校验：写入数据库，更新排行榜。
   - 校验失败：拒绝写入，标记为作弊。

2. 后端技术选型 (基于 FastAPI)

请选择您期望的数据库和数据存储方案：

A

SQLite (单文件)

最简开发 & 易部署。无需额外配置数据库服务，适合前期快速上线和中低并发量，数据备份只需复制文件。

B

PostgreSQL / MySQL

生产级关系型数据库。适合高并发和复杂查询，支持集群扩展，为全服排行与数据统计提供更好的支持。

3. 防作弊与性能权衡

混合模式优点

  • 盘中交易极致流畅，完全不受网络波动影响
  • 后端无需维护复杂的在线会话(Session)，服务器成本极低
  • 通过后端“交易日志重放校验”，低成本实现 99% 防作弊

潜在挑战

  • 无法防止玩家通过“本地存档回档（SL大法）”来反复刷完美行情
  • 如果不使用微信登录，单机游客防作弊难度大（可通过签名机制缓解）
